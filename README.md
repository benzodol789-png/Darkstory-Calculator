# Darkstory Calculator

เครื่องคิดเลขต้นทุนไอเทมเกม Darkstory — แปลงค่าเงิน (ทอง ↔ บาท), รายการไอเทมตลาด,
ราคาวัสดุอัปเกรด และค่าตีบวก/สืบทอด พร้อม sync ข้อมูลกับ Google Sheet

## วิธีใช้

1. ติดตั้ง Python 3.8 ขึ้นไป (ทดสอบบน 3.13) แล้ว `py -m pip install -r requirements.txt`
   (มีแค่ Pillow ตัวเดียว ใช้กับภาพพื้นหลังของธีม — ไม่มีก็รันได้ แต่พื้นหลังจะเป็นสีเรียบ)
2. คัดลอก `darkstory_config.example.json` เป็น `darkstory_config.json`
3. ใส่ลิงก์ Apps Script Web App ลงในช่อง `server_url`
4. รัน `py Darkstory_Calculator.py` (หรือดับเบิลคลิกไฟล์)

โปรแกรมทำงานได้แม้ยังไม่ตั้งค่า `server_url` — แค่จะกดโหลด/บันทึกไม่ได้เท่านั้น
ข้อมูลที่กรอกจะถูกเก็บไว้ในเครื่องที่ `darkstory_local.json` และโหลดกลับมาให้ตอนเปิดครั้งถัดไป

## ไฟล์ในโปรเจกต์

| ไฟล์ | หน้าที่ |
|---|---|
| `Darkstory_Calculator.py` | หน้าตาโปรแกรมและการเชื่อมต่อเซิร์ฟเวอร์ |
| `game_data.py` | ตารางข้อมูลเกม + ฟังก์ชันคำนวณ + ตัวตรวจโครงสร้างตาราง |
| `theme.py` | สี ฟอนต์ พื้นหลัง และหน้าต่างมุมโค้ง |
| `darkstory_config.json` | ลิงก์เซิร์ฟเวอร์และ token — **ห้าม commit หรือแจกต่อ** |
| `darkstory_local.json` | ข้อมูลที่เก็บไว้ในเครื่อง (สร้างเอง) |
| `darkstory.log` | บันทึกข้อผิดพลาด (สร้างเอง หมุนไฟล์ที่ 512 KB) |

## ธีมหน้าตา

ทุกอย่างที่เกี่ยวกับหน้าตาอยู่ใน `theme.py` ไฟล์เดียว — สี ฟอนต์ พื้นหลัง และตัวหน้าต่าง

- **พื้นหลัง** `DarkstoryฮBG1.jpg` (โทนอุ่น) คลุมทั้งหน้าต่าง ย่อแบบ aspect-fill แล้วคลุมม่านมืด
  เพราะภาพต้นฉบับมีตัวละครกลางจอ ถ้าไม่คลุมจะอ่านตัวหนังสือไม่ออก
- **แถบหัว** `DarkstoryฮBG2.jpg` ครอปเป็นแถบแนวนอน ไล่จางลงทางล่างให้ต่อกับเนื้อหาแบบไม่มีรอยต่อ
- **สี** ดูดมาจากภาพจริง (BG1 เป็นโทน hue ~23° ทั้งภาพ) แก้ได้ที่ `PALETTE` ใน `theme.py`
- **ฟอนต์** ปรับขนาดตามหน้าต่างอัตโนมัติ (ตัวคูณ 0.85–1.6) ใช้ named font ทั้งหมด
  จึงเปลี่ยนทีเดียวแล้วทุก widget ตามหมด ความสูงแถบหัว/แถบสถานะคิดจาก metric ของฟอนต์
  ไม่ใช่ค่าคงที่ ตัวหนังสือจึงไม่โดนตัดขอบตอนฟอนต์โต
- **มุมโค้ง** Windows 10 ไม่มีมุมโค้ง native (มีเฉพาะ Win11) จึงตัดรูปทรงหน้าต่างเองด้วย
  `SetWindowRgn` + `CreateRoundRectRgn` แล้ววาด title bar เอง — ลากย้าย ย่อ ขยาย
  และลากขอบปรับขนาดได้ทั้ง 8 ทิศ

**ข้อควรรู้ถ้าจะแก้ธีม:**

- `deiconify()` **ล้าง window region ทิ้ง** ต้องเรียก `refresh_region()` ใหม่ทุกครั้งหลังโชว์หน้าต่าง
  ไม่งั้นหน้าต่างจะโดนตัดค้างที่ขนาดเดิม
- ตัวหนังสือบนแถบหัวต้องเป็น canvas item ไม่ใช่ `Label` เพราะ Label มีพื้นหลังทึบจะบังภาพ
- `Combobox` แบบ readonly ต้องตั้ง `selectbackground` ด้วย ไม่งั้นจะมีแถบน้ำเงินของระบบทับ
- ถ้าไม่มี Pillow โปรแกรมยังรันได้ แต่พื้นหลังจะเป็นสีเรียบแทนภาพ

## ตั้งค่า Google Apps Script (ที่มาของ `server_url`)

`server_url` ไม่ได้มาจากที่ไหน ต้อง deploy เอง — เป็นลิงก์ Web App ที่ผูกกับ Google Sheet ของคุณ

1. เปิด Google Sheet ที่จะใช้เก็บข้อมูล
2. เมนู **ส่วนขยาย (Extensions) → Apps Script**
3. ลบโค้ดเดิมทิ้ง แล้ววางเนื้อหาจาก `AppsScript_Code.gs` ลงไป
4. ตั้ง `TOKEN` ในบรรทัดบนๆ เป็นข้อความสุ่ม (หรือปล่อย `""` ถ้ายังไม่อยากใช้)
5. กด **Run → setupSheets** หนึ่งครั้ง เพื่อสร้างชีต `currency` / `items` / `materials`
   พร้อมหัวคอลัมน์ที่ถูกต้อง (ครั้งแรกจะขออนุญาตเข้าถึงไฟล์ ให้กดอนุญาต)
6. กด **ทำให้ใช้งานได้ (Deploy) → การทำให้ใช้งานได้ใหม่ (New deployment)**
   - ประเภท: **แอปเว็บ (Web app)**
   - ดำเนินการในฐานะ (Execute as): **ฉัน (Me)**
   - ผู้ที่มีสิทธิ์เข้าถึง (Who has access): **ทุกคน (Anyone)**
     — จำเป็น ไม่งั้นโปรแกรมเข้าไม่ได้เพราะไม่ได้ล็อกอิน
7. คัดลอก **URL ของแอปเว็บ** ที่ลงท้ายด้วย `/exec` เอาไปใส่ `server_url`
   ใน `darkstory_config.json` และใส่ `token` ให้ตรงกับข้อ 4

> **ทุกครั้งที่แก้โค้ด Apps Script ต้อง Deploy ใหม่** ไม่งั้นของเดิมยังทำงานอยู่
> ถ้าเลือก "จัดการการทำให้ใช้งานได้ → แก้ไข → เวอร์ชันใหม่" ลิงก์จะเหมือนเดิม
> แต่ถ้ากด "New deployment" จะได้ลิงก์ใหม่ ต้องแก้ `darkstory_config.json` ด้วย

### หน้าตาชีตที่ถูกต้อง

แถวแรกคือชื่อคอลัมน์เสมอ และต้องแยกเป็นคนละช่อง (ห้ามรวมไว้ช่องเดียว)

| ชีต | A1 | B1 | ตัวอย่างแถวข้อมูล |
|---|---|---|---|
| `currency` | `key` | `value` | A2=`rate_gold_to_thb` B2=`0.85` |
| `items` | `name` | `price_gold` | A2=`ดาบเทพ` B2=`15000` |
| `materials` | `name` | `price_gold_per_unit` | A2=`หินดั้งเดิม` B2=`350` |

## Build เป็น .exe

ดับเบิลคลิก `build.bat` (หรือ `py -m PyInstaller --noconfirm --clean Darkstory_Calculator.spec`)
ได้ `dist\Darkstory_Calculator.exe` ไฟล์เดียว ~19 MB ไม่มีหน้าต่าง console
ต้องมี PyInstaller ก่อน: `py -m pip install pyinstaller`

`darkstory_config.json`, `darkstory_local.json` และ `darkstory.log` จะอยู่ **ข้าง exe**
ไม่ได้ฝังอยู่ในตัว exe จึงแก้ลิงก์เซิร์ฟเวอร์ได้โดยไม่ต้อง build ใหม่

**เวลาแก้ `Darkstory_Calculator.spec` ห้ามใส่โมดูลของ standard library ลงใน `excludes`**
โดยเฉพาะ `email` / `http` / `xml` — `urllib.request` เรียก `http.client` ซึ่ง import
`email.parser` ถ้าตัดออกจะ import พังตั้งแต่ก่อน logging จะเริ่มทำงาน แล้ว .exe จะขึ้น
error dialog เปล่าๆ โดยไม่มี `darkstory.log` ให้ดูเลย

ถ้า .exe เปิดไม่ขึ้น ให้ดู `darkstory.log` ข้าง exe เป็นอย่างแรก

## ตรวจตารางข้อมูล

เวลาเกมอัปเดตแล้วต้องแก้ตัวเลขในตาราง ให้รันคำสั่งนี้เพื่อตรวจว่าไม่พิมพ์ผิด:

```
py game_data.py
```

`validate_tables()` ตรวจ **โครงสร้าง** เท่านั้น — จำนวนคอลัมน์ครบไหม ระดับขาดไหม
ค่าเป็นบวกไหม เรียงจากน้อยไปมากตามเกรดไหม

`anomalies()` แยกรายงาน **จุดที่ตัวเลขสวนแนวโน้ม** ซึ่งเป็นข้อมูลจริงจากเกม ไม่ใช่ error
(ดูหัวข้อ "อย่าแก้ให้ตัวเลขสวย" ด้านล่าง)

โปรแกรมหลักเรียก `validate_tables()` ตอนเปิด ถ้าโครงสร้างพังจะเตือนก่อนให้ใช้งาน

## ความหมายของตาราง

- `UPGRADE_RED[lv][g]` = **ชิ้นส่วนหินดั้งเดิม (เศษแดง) ที่ใช้ตีจาก +(lv-1) ไป +lv**
  → ตีจาก +st ไป +en รวมแถว `st+1 .. en` (ตี +5 → +5 จึงเท่ากับ 0)
  ตัวอย่างตรวจสอบ: เกรดตำนาน ตีจาก +6 ไป +7 = `UPGRADE_RED[7][3]` = **131 ชิ้น**
- `INHERIT_SAME[lv][g]` = ค่าสืบทอด (ทอง) ไปเกรดเดิม — 6 คอลัมน์ = ทั่วไป..พระเจ้า
- `INHERIT_HIGHER[lv][c]` = ค่าสืบทอด (ทอง) ไปเกรดที่สูงขึ้น — 5 คอลัมน์ = **หายาก..พระเจ้า**
  ("ทั่วไป" เป็นเป้าหมายไม่ได้เพราะเป็นเกรดต่ำสุด)

### วัสดุอัปเกรด — อันไหนซื้อขายได้บ้าง

| วัสดุ | อัตราหลอม | ซื้อขายด้วยเหรียญทอง |
|---|---|---|
| ชิ้นส่วนหินดั้งเดิม | 10 ชิ้น = หินดั้งเดิม 1 ก้อน | ❌ ไม่ได้ |
| **หินดั้งเดิม** | — | ✅ **ได้** |
| ชิ้นส่วนหินดั้งเดิมแดง | 10 ชิ้น = พลอยสีแดงเข้ม 1 เม็ด | ❌ ไม่ได้ |
| พลอยสีแดงเข้ม | — | ❌ ไม่ได้ |

**มีแต่ `หินดั้งเดิม` เท่านั้นที่มีมูลค่าเป็นเหรียญทอง** แท็บ 📊 จึงตีราคาจากตัวนี้อย่างเดียว
โดยแสดงเป็นขั้น: ชิ้นส่วนที่ต้องใช้ → หลอมรวมได้กี่ก้อน → คิดเป็นทองเท่าไหร่

ฝั่งพลอยสีแดงเข้มไม่มีช่องราคาให้กรอกเลย (เจตนา) เพราะกรอกไปก็ไม่มีความหมาย
ส่วนแท็บวัสดุคำนวณให้ว่าชิ้นส่วนที่มีหลอมได้กี่เม็ด แต่ไม่ตีเป็นเงิน

**เศษที่หลอมไม่ครบ 10 ชิ้นก็นับเป็นทุนด้วย** ถึงจะเอาไปขายตอนนี้ไม่ได้ แต่มันคือของที่จ่ายไปแล้ว
มูลค่าจึงคิดตามสัดส่วน ไม่ปัดขึ้นและไม่ปัดทิ้ง:

```
มูลค่า = (จำนวนชิ้นส่วน / 10) x ราคาหินดั้งเดิมต่อก้อน
```

ตรวจสอบ: 455 ชิ้น (45 ก้อน + เศษ 5) ที่ก้อนละ 3.5 บาท = 45.5 x 3.5 = **159.25 บาท**

### สืบทอดข้ามเกรดแล้วระดับตีบวกจะลดลง

`HIGHER_RESULT_LEVEL` เก็บระดับที่เหลือหลังสืบทอดแบบ "ระดับสูงขึ้น" —
`+10..+14` ลด 4 ระดับ ตั้งแต่ `+15` ขึ้นไปลด 5 ระดับ (ทั้ง +14 และ +15 จึงเหลือ +10)
โปรแกรมจะขึ้นคำเตือนบรรทัดนี้ในผลการคำนวณเสมอเมื่อเลือกโหมดนี้

### ⚠️ อย่า "แก้ให้ตัวเลขสวย"

ตารางจริงจากเกมไม่ได้เรียบเป๊ะ และเคยมีการแก้ผิดมาแล้ว:

- `INHERIT_SAME[24][5] = 2,047,007` และ `[30][1] = 130,349` หลุดจากตัวคูณ 3/2.8 นิดหน่อย **แต่ถูกแล้ว**
- `INHERIT_HIGHER` แถว `lv15` คอลัมน์ 0-3 **ต่ำกว่า** lv14 จริงๆ (ตรงกับจุดที่ระดับหลังสืบทอด
  เปลี่ยนจากลบ 4 เป็นลบ 5 พอดี) — ในตารางต้นฉบับทำสีแดงกำกับไว้เอง

`validate_tables()` จึงตรวจแค่โครงสร้าง (จำนวนคอลัมน์ ระดับครบ ค่าเป็นบวก เรียงตามเกรด)
ส่วนจุดที่สวนแนวโน้มรายงานผ่าน `anomalies()` เป็นข้อมูลเฉยๆ ไม่ใช่ error

## เรื่องความปลอดภัย

ลิงก์ Apps Script คือกุญแจดอกเดียวที่กั้นการเข้าถึง Google Sheet
ใครที่ได้ลิงก์ไปก็อ่านและ**เขียนทับ**ชีตได้ ถ้า deploy แบบ "Anyone"

- เก็บลิงก์ไว้ใน `darkstory_config.json` เท่านั้น อย่าฝังในโค้ดและอย่าแจกไฟล์นี้ต่อ
- ถ้าเคยแจกลิงก์ออกไปแล้ว ให้ archive deployment เดิมแล้ว deploy ใหม่
- ตั้ง `token` แล้วให้ฝั่ง Apps Script ตรวจก่อนเขียน
- ถ้าใช้คนเดียว ตั้ง deployment เป็น "Only myself" จะปลอดภัยที่สุด
- ทางที่ปลอดภัยกว่า: เปิด public เฉพาะ `doGet` (อ่านอย่างเดียว) แล้วเขียนจากเครื่องเจ้าของเท่านั้น

## สิ่งที่ฝั่ง Apps Script ควรทำ

- `doGet` รับ `action=read&sheet=<ชื่อชีต>` คืน `{"success":true,"data":[{...},...]}`
- `doPost` รับ `action=update` — อ่านได้ทั้งจาก query string และ JSON body
  (โปรแกรมส่งไปทั้งสองทาง เพราะ Apps Script อาจ redirect จน body หาย)
- ก่อนเขียนทับ ควร copy ชีตไป backup tab และปฏิเสธ update ที่ทำจำนวนแถวหายเกิน 50%
- ตรวจ `token` ก่อนเขียนทุกครั้ง
